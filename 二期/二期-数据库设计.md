# 二期数据库设计 — RAG 知识库与综合推理

| 项目 | 内容 |
| ---- | ---- |
| **文档编号** | DB-PHASE2-2026-001 |
| **文档版本** | V1.0 |
| **依据文档** | 《二期-需求文档》V1.0；《二期-系统设计》V1.0；HLD-2026-001 v2.6 |
| **数据库** | PostgreSQL 16（业务元数据）；Milvus（向量，逻辑集合设计见第 5 节） |
| **约定** | 与一期一致：`BIGINT GENERATED ALWAYS AS IDENTITY` 主键；`TIMESTAMPTZ`；`JSONB`；软删 `is_deleted`；**不建 Unique Key**（仅 PK/FK） |

---

## 1. 设计概述

### 1.1 目标

支撑：

1. 知识库文档版本、切分、发布与审计；
2. 综合推理 Run/Step 透明落库与反馈；
3. 功能开关秒级可读；
4. 盲区/兜底日志与指标扩展；
5. 与一期 `suggestion_event` / `audit_log` / `adoption_daily_stat` 衔接。

### 1.2 表清单

| 序号 | 表名 | 类型 | 说明 |
| ---- | ---- | ---- | ---- |
| 1 | `kb_document` | 新增 | 知识库文档（含版本与发布态） |
| 2 | `kb_chunk` | 新增 | 文档切片（检索文本侧） |
| 3 | `kb_publish_log` | 新增 | 一键发布操作流水 |
| 4 | `kb_blind_spot` | 新增 | RAG 兜底/未命中问题 |
| 5 | `agent_run` | 新增 | 一次综合推理任务 |
| 6 | `agent_step` | 新增 | 推理步骤明细 |
| 7 | `agent_feedback` | 新增 | 顾问对推理的反馈 |
| 8 | `sys_feature_flag` | 新增 | 全局功能开关 |
| 9 | `advisor_notification` | 新增 | 顾问通知（知识库更新等） |
| 10 | `suggestion_event` | **变更** | 增加 mode / 关联 / 引用字段 |
| 11 | `adoption_daily_stat` | **变更** | 按 mode 扩展指标列（或新表） |
| 12 | `order` | **可选变更** | 补剩余课时等字段（若业务需要） |

一期既有表（`profile` / `customer_tag` / `tag` / `order` / `audit_log` 等）**复用**，Agent Capability 只读，不改主结构（订单字段见 4.3）。

### 1.3 ER 关系（逻辑）

```
sys_user ──┬── kb_document.uploaded_by / published_by
           ├── agent_run.advisor_user_id
           ├── agent_feedback.advisor_user_id
           └── advisor_notification.user_id

kb_document 1 ── * kb_chunk
kb_document 1 ── * kb_publish_log

agent_run 1 ── * agent_step
agent_run 1 ── 0..1 agent_feedback
agent_run 0..1 ── 1 suggestion_event   (suggestion_event.agent_run_id)

customer / conversation ── agent_run / suggestion_event（同现有）
```

### 2.1 `kb_document` — 知识库文档

| ---- | ---- | -- | ---- | ---- |

## 3. 既有表变更

### 3.1 `suggestion_event` 增量字段

| 字段 | 类型 | 空 | 默认 | 说明 |
| ---- | ---- | -- | ---- | ---- |
| mode | VARCHAR(16) | Y | `legacy` | `legacy` / `rag` / `agent` |
| agent_run_id | BIGINT | Y | | FK → agent_run.id（可后置回填） |
| fallback | BOOLEAN | Y | false | RAG/Agent 是否走兜底 |
| citations_json | JSONB | Y | | 引用列表（RAG/Agent 共用） |
| uncertainty_notes_json | JSONB | Y | | |

`type` 仍表示销售/客服；`mode` 表示生成路径。

**采纳口径扩展：** 使用率分母仍为曝光；报表按 `mode` 分组输出二期指标。

### 3.2 `adoption_daily_stat` 增量（方案 A，推荐）

在原表增加：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| mode | VARCHAR(16) | `legacy`/`rag`/`agent`；日统计按顾问+日+mode |
| fallback_cnt | INTEGER | 兜底次数 |
| agent_fail_cnt | INTEGER | 推理失败次数 |
| avg_task_latency_ms | INTEGER | 从曝光到采纳的平均耗时 |

> 因一期约定不建 Unique，应用层保证「一日一顾问一 mode」一行。

**方案 B：** 新建 `phase2_daily_stat`，一期表不动。若担心影响现网报表，选 B。

### 3.3 `order` 可选增量

需求场景 B「剩余课时」若现网 `order` 不足，建议增加：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| remain_lessons | INTEGER | 剩余课时 |
| product_type | VARCHAR(32) | 课程类型 |
| grade | VARCHAR(16) | 适用年级 |
| subject | VARCHAR(32) | 科目 |

若课时在外部系统，Capability `order_list` 可先返回现有字段 + `meta` 占位，本迭代可不改表。

## 4. 枚举与 JSON 约定

### 4.1 `sources_json` / `citations_json` 元素

```json
{
  "type": "profile_tag|kb_chunk|order|tag",
  "refId": "123",
  "label": "学生数学水平：根据画像标签",
  "updatedAt": "2026-08-01T00:00:00Z",

```

### 4.2 `agent_step.output_json` 脱敏

- 禁止落库完整手机号/证件；沿用一期 masking。
- 画像仅存 sections 摘要与 tag 名，不存加密 PII 原文。

## 5. 向量库（Milvus）逻辑设计

### 5.1 Collection：`kb_chunks`

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| id | INT64 | 与 `kb_chunk.id` 一致 |
| document_id | INT64 | |
| category | VARCHAR | |
| is_published | BOOL | |
| embedding | FLOAT_VECTOR(dim) | dim 随模型，如 768/1024 |

**索引：** HNSW / IVF_FLAT（按数据量选）。  
**过滤：** `is_published == true`，可选 `category in [...]`。

### 5.2 生命周期

| 事件 | PG | Milvus |
| ---- | -- | ------ |
| 解析完成 | insert kb_chunk | upsert 向量，`is_published=false` |
| 发布 | chunk.is_published=true | 更新标量或删旧插新 |
| 归档 | is_published=false / is_deleted | 过滤不可检索；定期物理删 |

业务检索以 PG `kb_chunk` 补全文；Milvus 只做召回 ID 列表。

## 6. Redis 键设计

| Key | 类型 | TTL | 用途 |
| ---- | ---- | --- | ---- |
| `feature_flag:agent_reasoning_enabled` | STRING | 无或长 | `0/1` |
| `feature_flag:kb_rag_enabled` | STRING | 无或长 | `0/1` |
| `agent:run:{id}:cancel` | STRING | 600s | 打断信号 |
| `sse:agent:{runId}` | STREAM/LIST | 短 | 可选步骤 replay |
| `stream:kb:published` | STREAM | — | 发布事件 |
| `stream:agent:run_finished` | STREAM | — | 指标消费 |

## 7. 数据生命周期

| 数据 | 保留 | 清理 |
| ---- | ---- | ---- |
| kb_document 归档版 | ≥ 12 个月 | 超期冷存对象文件 |
| kb_chunk + 向量 | 随文档 | 归档后可延迟删向量 |
| agent_run / step | ≥ 6 个月 | 汇总进日统计后可归档 |
| kb_blind_spot | 处理完可软删 | 产品导出后清理 |
| advisor_notification | 已读 30 天 | 定时任务 |
