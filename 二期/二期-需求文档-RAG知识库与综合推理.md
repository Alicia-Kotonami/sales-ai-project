## 1. 背景与目标

### 1.1 背景

「K12 用户画像推荐系统」MVP 已试运行约一个月。画像、话术、标签等一期核心能力运行正常，但一线顾问反馈两类系统尚未覆盖的痛点：

1. **机构背景信息查询**：家长打听集团历史、荣誉、资质等客观事实时，顾问需切出微信检索，易丢单。试运行顾问统计：平均每人每天约 2～3 次。
2. **跨模块组合型问题**：家长一次抛出学情 + 课程 + 价格等多问题打包时，顾问需手动跨画像、开班表、价格表等多处拼装回复，老顾问约需 10 分钟；新人则易漏答或敷衍。试运行数据分析：组合型问题约占全部对话近 **12%**。

根因：一期提供了「工具箱」（画像、话术、标签、日程等），但各工具之间不串联，AI 无法像资深顾问一样「综合」多信息源完成一次完整应答任务。

### 1.2 产品目标

分两层升级 AI 侧边栏能力：

| 层级 | 定位 | 一句话目标 |
| ---- | ---- | ---------- |
| **第一层 · 知识库查询（RAG）** | 解决「知道什么说什么」 | 家长问集团客观事实时，AI 基于官方资料据实回答，无出处不编造 |
| **第二层 · 综合推理** | 解决「想清楚再开口」 | 家长提出复杂组合问题时，AI 分步调用多能力模块查信息并拼装建议，顾问审核后发送 |

**业务价值预期：**

- 顾问从「操作工」变为「审核者」，复杂问题响应从约 10 分钟降至约 10 秒内（AI 推理 3～5 秒 + 顾问确认）。
- 新人与老人差距缩小：AI 补齐「查什么、按什么顺序查」的经验差。
- 单顾问每日可多跟进约 10～15 个客户（销售侧估算）。

### 1.3 设计原则

1. **有出处才说**：知识库回答必须基于检索命中内容；无命中走兜底话术。
2. **过程透明**：综合推理每一步在侧边栏可见，顾问可打断纠正。
3. **人机互补**：发送键始终在顾问手上；AI 给基于数据的建议，顾问掌握最新线下信息。
4. **可回退**：管理后台提供全局关停开关，秒级退回简化模式。

## 2. 需求范围

### 2.1 本期（第一期）范围内

**第一层 — 知识库查询**

- 家长询问集团客观事实时，AI 基于官方资料库据实回答
- 资料库由擎天学智提供和维护，运营人员通过管理后台自助上传/替换并一键生效
- 更新后自动推送通知给所有顾问
- 搜索匹配度不达标时走兜底话术（嵌入顾问姓名），不编造、不猜测

**第二层 — 综合推理**

- 家长提出需跨多类信息的复杂问题时，AI 分步规划 → 调用能力 → 综合生成建议
- 第一期打通五类信息入口：
  1. 知识库
  2. 客户画像
  3. 订单记录
  4. 标签分析
  5. 开班信息（静态资料）
- 侧边栏透明展示推理步骤；顾问可随时打断与修正
- 单次任务有步数上限；信息不全时主动标注，不强制结论
- 推理不确定时标注置信度/核实提示，引导顾问核实
- 所有建议需顾问确认后手动发送
- 顾问可对推理结果反馈；兜底/失败自动记日志反哺优化

### 2.2 明确不在本期范围

| 排除项 | 说明 |
| ------ | ---- |
| 主观评价类问题 | 如「你们老师好不好」「和 XX 机构比哪个好」 |
| 销售话术 / 客服流程 | 仍由现有 Chat / KF Chat 模块负责 |
| 实时课程名额 | 第二期对接教务系统后再做 |
| 日程查询能力 | 第二期视第一期效果再排期 |
| 语音直接回复 | 仍为侧边栏文字建议 |
| AI 自主发送 | 发送键始终在顾问手上 |

### 2.3 用户与角色

| 角色 | 职责 |
| ---- | ---- |
| 课程顾问 | 使用侧边栏查看知识库回答与综合推理建议，确认后发送；可反馈、可打断 |
| 运营人员 | 后台上传/替换知识库文档，一键生效 |
| 业务审核人 | 开班计划（教务主管）、荣誉资质（市场主管）、集团概况与 FAQ（销售总监）内容审核 |
| 超级管理员 | 控制综合推理全局关停开关 |
| 产品 / 技术 | 灰度指标监控、回退链路验收、评估是否全量 |

## 3. 功能需求

### 3.1 第一层：集团知识库（RAG）

#### 3.1.1 资料库内容范围

官方资料库至少覆盖四类文档：

| 类别 | 内容示例 | 内容审核责任 |
| ---- | -------- | ------------ |
| 集团概况 | 成立年限、正规性、品牌介绍等 | 销售总监（李娜）终审 |
| 开班计划 | 年级/科目班次、暑假班等（含价格） | 教务主管审核 |
| 荣誉资质 | 奖项名称、年份、颁奖方 | 市场主管审核 |
| 常见 FAQ | 价格、退费、试听、优惠政策等 | 销售总监终审 |

**内容来源：** 市场部宣传册、官网介绍、奖状清单、每学期开班通知等现成材料。初稿由市场部整理，对应业务负责人审核，销售总监最终签字。

#### 3.1.2 查询与回答规则

| 编号 | 需求描述 | 优先级 |
| ---- | -------- | ------ |
| FR-KB-01 | 当家长问题属于集团客观事实查询时，AI 检索知识库并基于命中片段组织自然语言回复 | P0 |
| FR-KB-02 | 回答内容须可追溯至资料库原文；不允许在无命中或低匹配时自由发挥 | P0 |
| FR-KB-03 | 匹配度不达标或无结果时，使用兜底话术，嵌入当前顾问姓名，引导家长继续找顾问（示例：「这个问题我暂时帮不上忙，您的专属课程顾问{顾问姓名}对这方面很了解，随时可以问她~」） | P0 |
| FR-KB-04 | 知识库更新后对顾问侧查询即时生效（一键生效） | P0 |
| FR-KB-05 | 知识库更新成功后，系统向全体顾问推送通知 | P1 |
| FR-KB-06 | 触发兜底时自动记录原始家长问题，形成「盲区数据」供内容补充 | P1 |

#### 3.1.3 管理后台 — 资料库管理

| 编号 | 需求描述 | 优先级 |
| ---- | -------- | ------ |
| FR-ADM-01 | 管理后台提供资料库管理入口，运营可上传、替换四类文档 | P0 |
| FR-ADM-02 | 支持一键生效；操作体验对标「发邮件」级别的低门槛 | P0 |
| FR-ADM-03 | 开班计划等含价格内容更新后，须有明确生效确认，降低「错一个零」类风险（流程侧由业务审核把关，系统侧需有操作可追溯） | P0 |

### 3.2 第二层：综合推理助手

#### 3.2.1 典型场景（验收用例锚点）

**场景 A — 王芳案例（组合推荐）：**

> 家长：「孩子现在初二，数学一直六七十分徘徊，英语不错能到 90。想暑假主攻数学，顺便提前接触物理。你们有什么合适的方案？大概什么价位？」

期望 AI 行为链路（示意）：

1. 查客户画像：年级、历史报班、沟通中提到的预算等 → 「这是谁」
2. 查开班信息：初二数学/物理暑假班匹配课程
3. 查知识库 FAQ：收费标准、暑期活动、退费/试听政策
4. 综合生成自然语言建议；侧边栏展示步骤进度；顾问确认后发送

**场景 B — 老学员续报：**

> 家长：「我之前报的课时还剩多少、再报有没有老学员优惠？」

期望调用：**订单记录** + **标签分析**（及必要时知识库优惠政策）。

#### 3.2.2 能力模块（第一期五入口）

| 编号 | 能力模块 | 提供信息 | 本期状态 |
| ---- | -------- | -------- | -------- |
| CAP-01 | 知识库 | 事实性资料、价格/政策 FAQ | 新增 |
| CAP-02 | 客户画像 | 年级、历史沟通、学情相关档案 | 对 AI 开放既有接口 |
| CAP-03 | 订单记录 | 历史报班、剩余课时等 | 对 AI 开放既有接口 |
| CAP-04 | 标签分析 | 薄弱科、意向等标签 | 对 AI 开放既有接口 |
| CAP-05 | 开班信息 | 班次、科目、静态开班计划 | 先用静态资料版 |

每个入口须向 AI 声明「我能提供什么信息」，供规划阶段选择调用。

#### 3.2.3 推理行为与约束

| 编号 | 需求描述 | 优先级 |
| ---- | -------- | ------ |
| FR-AG-01 | AI 收到复杂问题后，先规划需查询的信息类型，再按序调用对应能力模块，最后综合生成建议 | P0 |
| FR-AG-02 | 侧边栏逐步展示思考过程（如「正在了解学生情况…」「正在匹配课程…」「正在核对价格和优惠…」），含查了什么、查到了什么、基于什么判断 | P0 |
| FR-AG-03 | 顾问可在推理过程中打断并纠正方向 | P0 |
| FR-AG-04 | 单次综合任务有步数上限（约 2～3 步有效查询后应出结果，禁止无限查询） | P0 |
| FR-AG-05 | 信息不全或把握不足时，必须标注「基于部分信息推断，建议核实 XX」，不得装自信强行结论 | P0 |
| FR-AG-06 | 综合建议中关键信息项须标注来源与时效（示例：「学生数学水平：根据画像标签（最近更新：YYYY-MM-DD）」「推荐课程：根据 2026 暑期开班计划」） | P0 |
| FR-AG-07 | AI 仅生成侧边栏建议，发送须顾问手动确认；顾问可修改后发送 | P0 |
| FR-AG-08 | 综合推理端到端耗时目标 ≤ **5 秒**（侧边栏建议出现时间） | P0 |
| FR-AG-09 | 顾问可对本次推理结果一键反馈（认为有问题）；后台汇总为改进清单 | P1 |
| FR-AG-10 | 推理失败 / 走兜底时自动记录原始问题，反哺能力与逻辑优化 | P1 |

#### 3.2.4 管理后台 — 关停与风控

| 编号 | 需求描述 | 优先级 |
| ---- | -------- | ------ |
| FR-ADM-10 | 超级管理员可一键关闭「综合推理增强」功能，**秒级生效**，无需改代码 / 重启 / 发版 | P0 |
| FR-ADM-11 | 关闭后 AI 回退行为明确：仅走第一层知识库查询，和/或一期单模块回复建议（简化模式） | P0 |
| FR-ADM-12 | 关停开关与回退链路须作为上线前最高优先级技术验收项（CTO 亲自验收） | P0 |

## 5. 防幻觉与风控策略（验收约束）

会议确认的「防乱说」逻辑，作为硬性产品约束写入验收：

### 5.1 第一层（知识库）

- 匹配度门槛 + 兜底话术
- 无资料支撑禁止自由发挥

### 5.2 第二层（综合推理）

- **步骤透明**：完整思考过程对顾问可见
- **上限控制**：步数限制，避免越查越偏
- **不确定标注**：证据不足时标明并引导核实
- **顾问确认**：发送权在人

### 5.3 两层共用

- **关停开关**
- **反馈按钮**
- **兜底 / 失败日志**

**原则声明：** 若做不到过程透明，宁可不推第二层综合推理。

## 6. 验收标准与成功指标

### 6.1 第一层 — 知识库

| 指标 | 定义 | 初期参考线 |
| ---- | ---- | ---------- |
| 采纳率 | 顾问实际使用知识库建议的比例 | 灰度期持续观测 |
| 兜底率 | 触发兜底话术的比例 | 上线初期 30%～40% 正常；**连续一周 > 50%** → 先补内容再推全量 |
| 修改率 | 顾问对 AI 回答的修改比例 | 用于衡量准确度 |

### 6.2 第二层 — 综合推理

| 指标 | 定义 | 初期参考线 |
| ---- | ---- | ---------- |
| 采纳率 / 修改率 | 同第一层 | 灰度期持续观测 |
| 单次任务完成时间 | 从收到家长问题到顾问发出回复的总耗时 | 相对手工约 10 分钟应显著缩短；AI 侧建议出现 ≤ 5 秒 |
| 推理失败率 | AI 判断信息不够、无法给出建议的比例 | 初期 ≤ 25% 正常；**连续一周 > 40%** → 排查能力模块或推理逻辑 |
| 顾问满意度（定性） | 每周抽 5 名顾问电话访谈 | 固定两问：「这周 AI 推理有没有帮到你」「有没有哪次觉得查的方向完全不对」 |

### 6.3 技术验收门禁（上线前必须通过）

1. 关停开关秒级生效，且回退后 AI 行为确认为简化模式（完整回退链路测试）。
2. 综合推理耗时不超过 5 秒。
3. 五项能力接口可用，且王芳案例（场景 A）可端到端跑通。
4. 无命中 / 低置信场景均不出现编造性答复。

### 6.4 灰度与全量决策

| 阶段 | 规模 | 说明 |
| ---- | ---- | ---- |
| 内部测试 | 研发侧 | 开发完成后 |
| 灰度 | 30 名顾问（15 新人 + 15 老顾问，销售总监选定） | 约 1 周；每日同步采纳率 / 兜底率 / 修改率 / 推理失败率 / 任务完成时间 |
| 全量 | 约 300 名顾问 | 灰度评估报告评审通过后 |

**管理层节点：** 约一个月内需出具全量上线且稳定运行的数据报告。

## 8. 依赖与风险

| 类型 | 说明 | 应对 |
| ---- | ---- | ---- |
| 内容依赖 | 知识库质量与审核进度直接影响兜底率 | 销售总监牵头审核签字；盲区日志反哺补内容 |
| 数据质量 | 画像/标签非 100% 准确，错误数据会导致错误推荐 | 来源时效标注 + 顾问最终确认 |
| 推理跑偏 | 初期可能查错顺序或方向 | 步骤透明可打断；步数上限；失败率监控 |
| 时效资料 | 开班计划过期即错（如暑假数据到 9 月失效） | 后台自助更新 + 通知顾问 |
| 最坏情况 | 上线后大面积推理出错 | 全局关停开关秒级回退简化模式 |

## 9. 术语表

| 术语 | 含义 |
| ---- | ---- |
| RAG | Retrieval-Augmented Generation，检索增强生成：先查资料再生成回答 |
| 知识库 / 资料库 | 集团官方四类文档构成的可检索语料 |

| 简化模式 | 关闭综合推理后，仅知识库查询和/或一期单模块建议的回退状态 |
