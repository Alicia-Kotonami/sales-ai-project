## 二、会议背景与目的

擎天学智教育集团是一家全国性K12课外辅导机构，旗下拥有超过300名课程顾问（课程顾问），通过企业微信与家长进行日常沟通、课程推荐和售后服务。随着业务规模的快速扩张，集团面临以下几个核心痛点：

1. **客户信息分散**：每位课程顾问依靠个人笔记或脑力记忆跟进客户，没有统一的客户画像视图，人员离职导致客户信息断层严重。
2. **沟通质量参差不齐**：资深顾问转化率高，但新人培养周期长达3个月以上，期间沟通质量堪忧，直接影响续费率和转介绍率。
3. **标签管理混乱**：学员标签（如"小升初冲刺""数学薄弱""高意向"等）由各顾问自行标注，标准不统一，管理层无法准确掌握客户分布。
4. **跟进遗漏严重**：课程顾问同时跟进200-400名客户，经常忘记跟进节点，错过关键转化窗口。
5. **数据孤岛**：售前沟通记录和售后客服记录分属不同系统，无法形成完整的客户生命周期视图。

本次会议旨在明确AI驱动的智能销售辅助系统的核心需求，确定产品方向与开发计划。



```
挖掘用户痛点背后的真实需求,重点关注,钱,人(角色),数据流向

钱:续费(老客户),转介绍(新客户)
人:学员,家长,课程(资深)顾问,管理层,售前,售后
数1:客户数据->数据画像 -> 客户分布
数2:资深顾问 -> 顾问
数3:学员信息 -> 学员标签
数4:客户跟进节点提醒
```

## 三、会议讨论纪要

### 主题一：开场 — 为什么我们需要这个系统

**张建国（CEO）**："我先开个头。去年我们做了6个亿的营收，但销售团队扩到300人之后，人效反而下降了。李娜，你来说说一线的真实情况。"

**李娜（销售总监）**："确实。我们新招的顾问，前三个月基本上是在'喂客户'——把意向客户分配给他们，但转化率平均只有资深顾问的三分之一。最让我头疼的是，资深顾问手里积累了上千条沟通经验，但这些经验没法复制。新人是靠自己在微信群里一条一条摸索出来的。"

**赵明（飞流科技）**："所以核心诉求是：把资深顾问的沟通经验'数字化'，然后通过AI赋能到每一个顾问身上？"

**张建国（CEO）**："对，就是这个意思。我们不需要AI替人做决策，但我们需要AI帮人做功课——客户分析、话术建议、跟进提醒，这些完全可以交给AI。"

---

### 主题二：客户画像 — "把碎片拼成一张完整的图"

**陈思远（产品经理）**："我们先聊第一个模块：客户画像。李总，目前的客户信息是怎么管理的？"

**李娜（销售总监）**："说实话，很原始。有的顾问用Excel，有的用手机备忘录，还有人靠脑子记。一个家长可能跟我们沟通了半年，但换一个顾问接手，一切从零开始。孩子上几年级、什么科目薄弱、家长关注价格还是关注师资——这些信息全在上一任顾问脑子里。"

**张建国（CEO）**："上次有个案例让我很触动。一位家长跟进了四个月，结果顾问离职了，新顾问打电话过去'您好请问孩子几年级了'——家长当场就炸了。这就是我们说的客户信息断层。"

**赵明（飞流科技）**："我们设计的方案是这样的：系统后台会自动从企业微信聊天记录、订单记录、客服记录中提取结构化信息，生成360度的客户画像。包含基础信息（学生姓名、年级、学校）、学情分析（强弱科目、成绩变化、学习目标）、沟通偏好（回复时间、价格敏感度、决策风格），以及跟进历史时间线。"

**王宏远（CTO）**："有一个关键点——这些画像信息能不能保证准确？如果AI分析错了，顾问照单全收，反而会出问题。"

**赵明（飞流科技）**："我们设计了一个'人机协作'机制。AI生成的画像默认是'草稿'状态，顾问确认后才生效。而且每次AI分析会标注置信度和信息来源，让顾问可以追溯判断。"

**李娜（销售总监）**："这个好。但还有一个问题——300个顾问，每个人使用习惯不一样。如果系统太复杂，有些人就是不爱用。"

**陈思远（产品经理）**："所以我们设计了智能侧边栏。顾问在企业微信里聊天的时候，侧边栏自动展示客户画像，不需要跳转系统。聊天过程中有新信息，AI会实时更新画像建议。"

**王宏远（CTO）**："侧边栏走的是SSE流式推送，响应应该在200毫秒以内。"

**赵明（飞流科技）**："技术上我们有把握。"

---

### 主题三：智能回复建议 — "让每个顾问都有金牌销售的沟通能力"

**张建国（CEO）**："李娜，你下午跟我提的那个'回复建议'的想法，详细说说。"

**李娜（销售总监）**："我们现在每天处理几万条家长咨询。家长问的问题来来去去就是那些：'你们价格多少''有什么课程适合我孩子''能不能试听'。资深顾问对这些问题的回复已经打磨了无数遍，转化率高。但新人可能回复得很生硬，甚至踩雷——比如家长问价格，新人直接报价，然后家长说'太贵了'，然后就没了。"

**赵明（飞流科技）**："所以是想让AI实时分析家长的消息，然后推荐最佳回复话术？"

**李娜（销售总监）**："对！而且最好能区分场景——售前和售后的话术不一样，小学和初中的家长关注点不一样。"

**陈思远（产品经理）**："我们计划分两个子模块：销售回复建议和客服回复建议。销售场景偏转化和逼单，客服场景偏服务和留存。AI会根据客户画像和当前聊天上下文综合推荐。"

**王宏远（CTO）**："这里有一个技术难点——家长发一条语音或者一段50秒的语音，AI能不能理解？"

**赵明（飞流科技）**："我们接入了语音转文字的能力，语音消息会自动转成文本后再做语义分析。但有个原则——所有AI生成的回复只是建议，顾问需要自己点发送按钮，我们不会自动代发。"

**张建国（CEO）**："对，这个原则很重要。AI是辅助，不是代劳。出了事还是我们的人负责。"

---

### 主题四：智能标签 — "从各自为政到统一标准"

**陈思远（产品经理）**："李总，现在标签这块的管理情况如何？"

**李娜（销售总监）**："乱。'A类客户''高意向''近期报班'这些标签每个顾问自己打，含义不统一。有人觉得咨询超过三次就算高意向，有人觉得试听过的才算。总部做数据分析的时候，数据完全没法用。"

**王宏远（CTO）**："上次运营部出了个报告，显示高意向客户转化率只有12%，我一查，很多人把'刚刚加微信'的客户都标成了高意向。"

**张建国（CEO）**：（笑）"自己骗自己。"

**陈思远（产品经理）**："我们设计的方案是：系统根据客户的聊天行为和画像特征，自动推荐标签。比如一个家长连续三天咨询初中数学课程，AI就推荐添加'初中数学''高意向''近期决策'等标签。同时如果AI发现某个标签已经不合适了，也会推荐移除。所有推荐都需要顾问确认。"

**李娜（销售总监）**："能不能把标签和跟进策略关联起来？比如某个标签对应的客户应该怎么跟进。"

**陈思远（产品经理）**："可以的，标签体系可以由你们管理后台自定义。每个标签可以配置跟进SOP."

**张建国（CEO）**："标签这件事一定要做标准。一个客户身上带着30个标签也没用，关键是标签要可衡量、可行动。"

---

### 主题五：智能日程与提醒 — "别再错过任何一个关键节点"

**李娜（销售总监）**："还有一个痛点——我们的顾问每人跟200-400个客户，试听跟进、续费提醒、生日关怀，这些时间节点经常被遗漏。上个月有顾问把人家孩子的试听课时间都记错了，家长来了没人接待，印象分直接为零。"

**赵明（飞流科技）**："这个可以通过AI语义解析来实现。系统自动识别聊天中提到的时间信息，比如家长说'下周孩子考完试我们来看看课程'，AI就自动创建一个待办提醒。同时，续费节点、试听回访这些周期性任务，系统可以根据历史数据自动预测并创建日程。日程也会同步到企业微信日历。"

**王宏远（CTO）**："安全和隐私方面，日程信息涉及客户隐私，访问权限需要严格控制。另外提醒频率不能让用户觉得被打扰。"

**陈思远（产品经理）**："我们遵循最小通知原则。只有高优先级的事项才会做强提醒，一般事项只做侧边栏弱提示。用户可以自定义提醒偏好。"

---

### 主题六：管理后台 — "让管理层看得见"

**张建国（CEO）**："最后说说管理后台。我现在想看整个销售团队的数据，要么找数据组出报表，要么去问李娜。我想要一个我能自己看的。"

**陈思远（产品经理）**："管理后端的功能定位是管理层和运营人员的统一工作台。包括：员工管理（顾问信息、权限）、客户管理（客户列表、画像查看、沟通记录回溯）、订单管理、标签管理（标签体系定义和统计分析），以及核心看板（转化漏斗、续费率、顾问人效等）。"

**李娜（销售总监）**："有一个功能我非常需要——能看到每个顾问的AI采纳率。哪些顾问经常采纳AI建议，哪些从来不采纳，数据拉出来就知道谁需要培训。"

**赵明（飞流科技）**："这个指标我们会埋点统计。后台会有详细的AI使用分析报表。"

**王宏远（CTO）**："后台的用户角色至少分三层：超级管理员、区域主管、普通顾问。权限粒度要支持按功能模块和数据范围控制。"

**陈思远（产品经理）**："当然。每个角色能看到什么、能操作什么，都可以在权限管理中配置。"

### 主题七：争议与共识 — "人机协作"的边界

**王宏远（CTO）**："我还有一个顾虑。AI建议推送到企业微信侧边栏，如果并发量大的时候，会不会影响企业微信本身的使用体验？"

**赵明（飞流科技）**："飞流科技有成熟的微服务架构，AI服务是独立部署的，不会影响企业微信主流程。我们的接口设计遵循企业微信的开发规范，不会有性能风险。"

**张建国（CEO）**："责任边界问题我想明确一下——如果AI提供的话术建议有问题，责任在谁？"

**赵明（飞流科技）**："我们在系统设计上遵循'重建议、轻代劳'原则。所有AI生成的内容都是建议性质，由人工确认后手动操作。在界面上会明确标注'AI建议'，让客户知道这是机器生成的。但最终发送的内容由使用者负责。"

**张建国（CEO）**："好，这个明确下来写进合同。"

**李娜（销售总监）**："赵总，我还有一个问题——AI的学习能力。我们的客户群体和话术风格跟别的教育机构不一样，AI能适应我们吗？"

**赵明（飞流科技）**："可以。系统上线时会基于你们的历史聊天记录做微调训练。上线后还有持续学习机制，顾问对建议的采纳或拒绝行为会作为反馈信号，优化后续推荐质量。不过这个数据闭环需要一到两个月的积累才能看到明显提升。"

**李娜（销售总监）**："那就比较理想了。"

## 四、核心需求整理

经会议讨论，确认以下六大核心模块：

### 模块一：AI客户画像生成
- 从企业微信聊天记录、订单数据、客服记录中自动提取客户信息
- 生成360度客户画像：基本信息、学情分析、沟通偏好、跟进历史
- 画像以"草稿"状态呈现，顾问确认后生效
- 侧边栏实时展示画像信息，无需跳转系统



```
agent1.1(聊天记录+订单+客服记录) -> 客户基本信息
agent1(聊天记录+订单+客服记录) -> 画像(草稿):基本信息,学情,偏好,跟进历史 -> 侧边栏 -> 确认
```



### 模块二：AI智能 回复建议
- **销售回复建议**：基于客户画像和聊天上下文，推荐最优话术
- **客服回复建议**：面向售后场景的回复建议
- 区分不同教学阶段（小学/初中/高中）和沟通场景
- 支持语音消息转文字后分析
- 所有建议需人工确认后手动发送

```
agent2(画像,教学阶段,沟通场景) -> 销售回复建议 -> 确认 -> 发送
agent3(画像,教学阶段,沟通场景) -> 客服回复建议 -> 确认 -> 发生
STT(语音) -> 文本
```



### 模块三：AI智能标签推荐
- 自动分析客户行为，推荐添加/移除标签
- 支持自定义标签体系和跟进SOP
- 标签推荐需顾问确认后生效
- 标签数据支持统计分析

```
agent4(客户行为) -> 标签增删改 -> 确认
自定义标签()
根据SOP()
标签分布(标签)
```

### 模块四：AI智能日程与提醒
- 自动识别聊天中的时间信息，创建待办事项
- 基于历史数据预测续费/试听回访节点
- 同步企业微信日历
- 分级提醒机制（强提醒/弱提示）

### 模块五：管理后台
- 员工管理（角色、权限、组织架构）
- 客户管理（列表、画像、沟通记录回溯）
- 订单管理
- 标签管理（体系定义与统计）
- 数据看板（转化漏斗、续费率、人效分析）
- AI采纳率统计

### 模块六：企业微信侧边栏集成
- 客户画像、回复建议、标签、日程一站式操作
- SSE流式推送，低延迟响应
